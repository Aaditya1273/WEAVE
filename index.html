What makes it different

Most agent integrations bolt a chatbot onto an editor. WEAVE treats the agent as a second author with real boundaries.

01

Transactions, not one-off edits

“Make this homepage feel more premium” becomes one proposal containing five operations. You see each one’s before and after, edit the copy you disagree with, skip what you don’t want — and the rest commits atomically as a single revision.

02

Concurrency you can trust

Every proposal is pinned to the revision the agent was reasoning about. If you edit the page first, the proposal is refused as stale instead of being applied to state the agent never saw. Your work is never silently overwritten.

03

One pipeline for both authors

A human drag and an agent move produce the same mutation, the same generated source and the same undo entry. There is no second write path, so there is no class of change only one of you can make or reverse.

04

Agent-ready output

Publishing produces your real Next.js source plus a capability manifest and a small runtime, so the site you ship can expose its own structure to the next agent. No proprietary format, no lock-in.

The WebMCP surface

Nine typed tools, registered with the browser’s model-context runtime. Descriptions state product intent; annotations declare real consequences.

ToolAccessWhat it does
weave_get_contextreadPage, revision, selection, typed sections, bounded element tree
weave_get_selectionreadFull detail for the element you have selected
weave_add_sectionwriteInsert a designed section from the shared library
weave_update_elementwriteText, name, visibility, safe styles and attributes
weave_move_elementwriteReorder or re-parent a section or element
weave_delete_elementdestructiveRemove an element and its children
weave_propose_changeshuman reviewSubmit several edits as one reviewable proposal
weave_validate_sitereadReal findings plus an explainable agent-readiness score
weave_publish_sitehuman approvalRequest a publish — only your click performs one

Where this actually stands

  • WebMCP is an emerging browser API. If your browser exposes no runtime, the editor says so plainly — the tools remain usable through the built-in developer console, which calls the identical implementations.
  • Agent context is pull-based. WEAVE bumps a revision on every change and agents re-read; it does not pretend to push page content the shipping API cannot push.
  • “Publish” here means persist and download a complete, agent-ready bundle. No third-party deployment provider is contacted or simulated.
  • The runtime shipped with a published site is read-only plus same-site navigation, by design.
